# 02｜手機 UI／UX 規格

## 體驗方向

**像調到一個懂你的電台，不像在管理五個 API。** 先讓人輸入感覺；需要登入或處理權限時再解釋。播放器要安定，Bridge 要容易看懂，控制不要藏在手勢後面。

本次視覺預設：暖白背景、深松綠字與控制、少量焦糖色提示、抽象唱片式聲景。屬本次設計提案，未宣稱是使用者既有品牌。真實 Spotify artwork 必須按供應商品牌規則原樣呈現，不套抽象濾鏡或把文字蓋在上面。[R11]

## 資訊架構

三個底部入口：**開台／收聽／設定**。無獨立桌面側欄。節目單、Bridge 完整說明、微調與播放環境都以底部 sheet 或可回上一層的全高 sheet 呈現。窄螢幕不可讓多層 modal 套在一起。

```
開台（Seed） → 生成進度 → 節目準備好 → 使用者點播放 → 收聽
                                      ├─ 這首為什麼（Bridge sheet）
                                      ├─ 接下來（Queue sheet）
                                      └─ 微調（Tune sheet）
設定 → DJ 說話量／播放環境／資料說明／重新連線
```

### 導覽規則

- 顯式三個 tab，不用 icon-only。未生成 Show 時「收聽」顯示有下一步的空狀態，而不是 disabled 死區。
- 改 tab、展開 Bridge、看 Queue 不重建或暫停 playback engine。
- 有播放中的 Show 時，離開收聽頁保留 mini-player，位於底部導覽上方；收聽頁不再重複一個 mini-player。
- Browser Back 優先關閉目前 sheet，再回上一主要頁；焦點回到觸發鍵。不可意外退到 OAuth 前頁或清空播放。
- 關閉 sheet 有 48px 顯式按鈕；下滑關閉僅加分。Android back、Escape、VoiceOver 都有等價路徑。

## 畫面與互動

### S01 開台／首次進入

第一眼看到品牌、小段價值說明「用一首歌，找到同一種感覺」、一個明確輸入區與主要動作「為我開台」。不要先擺出 OAuth、API key、側欄與十個 filter。

輸入模式用 segmented control：感覺、歌曲、聲音。輸入 1–500 grapheme clusters。範例 chip「深夜，還不想睡」「暖一點，別太躁」「剛練完舞，累但很爽」。按 chip 只填入，不立即花費生成額度。placeholder 不是唯一標籤。

歌曲模式提供歌名＋藝人兩欄，避免同名混淆；若貼 Spotify URL，顯示已辨識連結，但不能把 Spotify 回傳 metadata 餵入模型。請使用者確認自行輸入的歌名與描述，或走經核可的獨立資料流程。首版不做檔案上傳、錄音與麥克風權限。

CTA 在鍵盤升起時依 `visualViewport`／容器佈局避讓，不被底部 tab 疊住。Enter 在 textarea 換行；明確按鈕才送出。輸入法 composing 時不可誤送。

已有播放時，新開台按鈕文案「建立下一段」，預設不停止當前曲。只有明示「現在切換」才打斷，並可返回。

### S02 生成中

保留 Seed、取消按鈕、真實階段文字：理解感覺 → 配對聲景 → 確認曲目 → 準備節目。前端依後端實際 phase，不用固定計時器假裝 API 完成。進度不宣佈「正在聽你的歌」；首版沒有音訊分析。

stage 完成才顯示 check。20 秒以上顯示「這次找歌比較久，你可以先取消，輸入會保留」。60 秒 timeout 轉可恢復狀態。取消令 generationId 失效，網路晚到結果不能切換畫面或開播。

### S03 準備好／尚未播放

保留節目名稱、Seed 摘要、感覺鉤子及四面向的簡潔 chips；顯示「已準備 5 首」或真實可用數量。主動作「開始收聽」，由使用者手勢啟動音訊。準備好不等於播放中，不能跳動進度條。

沒有任何曲目可播時，仍可保留解說與待驗證清單，但標示「尚無可播曲目」，CTA 為「修改感覺」／可用外連，不用空白播放器。

### S04 收聽頁（首屏優先）

由上到下：節目脈絡與 provider 狀態 → 曲目 artwork／展示聲景 → 曲名／藝人 → 短版 Bridge → 播放進度 → 主要控制 → 接下來一首 → 微調入口。短螢幕可縮 artwork 到 128–180px，不能把播放鍵推到兩屏外。

Bridge 是可點開的內容塊，標題「為什麼是這首」，預設最多 2–3 行；「完整理由」顯式可按。不是只顯示「適合你的心情」。

主控制中間 64px play/pause，右邊下一首，左邊「重播本曲」而非語意不清的上一首。首版重播不自動重念 DJ；重聽串詞是 Bridge sheet 的獨立操作，且僅在 provider 允許時可用。

進度可拖動時才呈現 range control，44–48px 觸控區；拖動本機先預覽秒數，放開後單次 seek。不可播或外連模式不顯示假進度。TTS 期間顯示「DJ 正在介紹」與「跳過介紹」；同一主播放鍵暫停當下 speech，不偷偷切歌。

喜歡／不合適屬明示回饋而非暗中讀取情緒。不合適可展開原因「太躁／太慢／音色不對」，即使不選也可略過。Spotify-derived 回饋存取與後續模型用途受 G0 限制，首版不自動建立長期 profile。

### S05 Bridge sheet

顯示：感覺鉤子、一個具體連結、三個 vibe 詞、來源可信度與已知限制。可切看 Sonic DNA 四面向。對歌曲事實沒有可靠根據時標記「推薦推測，尚未聽音驗證」，不是把主觀比喻包裝成精準分析。

若有 transitionBridge，明示「接續：前一首 → 這一首」。前一首被略過或調序後此區塊隱藏，保留 seedBridge。展開理由不生成新一輪 LLM。

### S06 節目單 sheet

首行「這一段 · 5 首」，每列顯示順序、曲名、藝人、簡短 Bridge、已播／正在播／待播／不可用狀態。正在播的列不可被無意移除；點其他曲列預設看資訊，另有清楚的「現在播放」操作。

移除僅影響未播放 Segment，toast 提供 5 秒復原。此 5 秒是 UI 交互窗口不是 future work 時間承諾。保留現在曲；所有 queue mutation 增加 queueRevision。可拖曳排序放階段 1，不在 MVP 同時做拖曳／滑動刪除；首版若提供上移／下移按鈕，必須同步驗證 Bridge，且鍵盤可用。

### S07 微調 sheet

先顯示「只調整接下來，不打斷這首」。快速方向「更放鬆／更有推進／多點人聲／更陌生」，可填短句。選項只是填入獨立 user preference，不把情緒速度宣稱為 BPM。

主 CTA「套用到接下來」，在新的 Show tail 完成前保留舊 tail；取消不變更任何曲目。重複點只建立一個 job。新 tail ready 後 toast 告知替換了幾首，不強迫切至新曲。

### S08 設定／播放環境

首版只有必要設定：DJ 開關、短版／標準串詞、語音聲線（伺服器允許值）、播放環境狀態、資料說明與清除本機設定。無 token／key 輸入欄。預設用 mock 時不可顯示「已連接 Spotify」。

Spotify 開關關閉時顯示「Spotify 尚未啟用，需先完成整合核對」；未連線顯示「連接 Spotify」；權限不足顯示可理解原因。未支援的系統音量不要畫出有效 slider；說明「請使用手機音量鍵」。

### S09 系統阻擋／錯誤恢復

| 狀態 | 告知什麼 | 主要操作 | 保留什麼 |
|---|---|---|---|
| 自動播放被擋 | 手機需要一次點擊才能繼續 | 點一下繼續 | 目前 Segment 與進度 |
| SDK 裝置離線 | 這個播放裝置目前未連線 | 重新連線 | Show，不自動搶播放權 |
| Premium／allowlist 不符 | 帳號目前不能在此播放 | 看播放環境／外連 | 清單與理由 |
| 429／quota exceeded | 服務目前達使用限制 | 稍後手動重試／看既有節目 | 不在背景無限重試 |
| TTS 失敗 | 介紹暫時無法播放，文字仍可看 | 跳過介紹 | 當首音樂可繼續 |
| 部分找不到歌 | 已確認 N 首，部分候選暫無法使用 | 聽 N 首／重新選歌 | 已確認者 |
| 網路中斷 | 音樂連線中斷，不是你按了暫停 | 重新連線 | 最後已確認進度 |
| session 失效 | 工作階段已過期 | 重新登入／重新建立 | Seed 草稿（若仍在本機） |
| 外連模式 | 將在 Spotify 開啟，這裡不控制播放 | 到 Spotify 收聽 | 不假裝知道外部進度 |

## 版面與拇指操作規格

- 主欄最大 480px；desktop 可附說明欄，但控制層級不改成管理台。
- 水平留白 20px；360 以下 16px。底部 tab 高至少 64px，加 `env(safe-area-inset-bottom)`；mini-player 另佔 64–72px。
- 使用 `min-height:100dvh` 搭配可捲動內容；避免只用 `100vh` 導致行動網址列遮擋。
- 只有一個主要捲動容器；sheet 內容可獨立捲動並鎖背景。focus 不被黏底列擋住。
- 正文字體至少 16px，行高 1.55–1.7；歌名長可兩行，藝人長可展開。不要用極小字把內容硬塞首屏。
- 操作區大於視覺圖示；相鄰破壞操作保留間距。主要動作靠近中下區，不以左上角小按鈕為唯一路徑。

## 動效與可及性

頁面轉場 160–220ms、sheet 220–280ms、press 80–120ms，皆為設計目標。`prefers-reduced-motion` 取消位移、脈動與轉盤效果。動畫只能表示「播放狀態」，不得偽裝成真實音訊波形或 Spotify 音訊分析。

正常文字對比 ≥4.5:1；大字 ≥3:1；icon、focus、重要邊界另驗證。狀態不能只靠顏色。所有 icon 有 accessible name；switch 有 checked；dialog 有 label、focus trap、返回焦點。`aria-live=polite` 只讀階段／曲目變更，不每秒念進度。[R12/R13]

## UI 驗收不接受

把長篇 JSON、錯誤堆疊、英文工程代號直接露出；桌面三欄硬擠手機；只有滑動才能刪除／關閉；底部播放器遮住提交鍵；開頁即播；尚未播放卻進度跳動；用 Toast 取代需要操作的重大錯誤；用精美假 UI 代替真實能力標示。
